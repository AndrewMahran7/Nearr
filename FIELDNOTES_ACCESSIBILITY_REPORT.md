# Fieldnotes accessibility report

This report records implementation and automated evidence for the Fieldnotes worktree. It is not a blanket WCAG conformance or iOS accessibility acceptance claim. Native VoiceOver, maximum Dynamic Type, keyboard/focus behavior and the iOS Share Extension host still require device validation. The native comparison and build reports own any later device evidence.

## What is implemented

| Area | Implemented behavior | Evidence and remaining boundary |
| --- | --- | --- |
| Light/Dark readability | Shared semantic text, secondary text and accessible accent colors replace the previous low-contrast accents. Botanical utility buttons, warm save gradients and success/warning/error pairs have distinct foreground roles. Onboarding adapts to the selected theme rather than forcing Light. | Foundation tests verify 30 semantic text/background combinations at 4.5:1 or better. This does not prove contrast over every photo, native map style, disabled control or composed overlay. |
| Text scaling | System typography remains; shared buttons use minimum heights, padding and shrinking/wrapping text rather than fixed text boxes. Saved rows remove title truncation at larger font scales. Review panes stack at small widths or larger text. Onboarding frames and practice sheets scroll, and the password input grows vertically. | Host tests exercise 100/150/200% practice and 100/150/220% Saved branches. They do not measure native glyph layout. Maximum accessibility sizes and landscape require device checks. |
| Touch targets | Shared IconButton/FilterChip, map dock controls, detail More/Share, gallery arrows/close, practice close/back and review selection controls use at least 44-point targets. Shared primary buttons have a 50-point minimum height. | Source and responder-tree checks establish declared geometry. Actual map-marker hit areas, adjacent targets and extension-host clipping remain native acceptance items. |
| Labels and roles | Map and Saved tabs expose selection. Markers identify the place and selected state. Icon-only close, More, directions, gallery paging, search and account controls have explicit labels. Review controls expose radio/checkbox state separately from photo inspection. | Automated review renders check independent photo and selection targets. VoiceOver reading order, grouped labels and redundant announcements have not been accepted on iOS. |
| Forms and errors | Inputs expose meaningful labels; shared inputs show a focus border. Password visibility controls announce Show/Hide password. Buttons expose disabled/busy states, and auth/real-practice errors use alert semantics where provided. Permission switches are labelled. | Keyboard avoidance, secure-field announcements, provider native-button layout and recovery focus require a device walkthrough. |
| Detail and modal actions | More and gallery expose modal accessibility semantics. Destructive removal remains an explicit action with confirmation. Gallery has indexed photo labels and Previous/Next controls with disabled endpoints, so browsing does not require a swipe gesture. | Verify initial focus, focus containment, backdrop exclusion and return focus after dismissing gallery, More, note editing and correction. No global focus-restoration guarantee is claimed. |
| Truthful state | Activity status uses text and icons, not color alone. Possible/area matches, unavailable source media, failed photos, pending recognition and duplicate outcomes remain visible. Practice is labelled and real queue results are not simulated by animation. | Check announcement frequency under a changing real job and ensure important updates are discoverable without repeated interruptions. |
| Reduce Motion | The shared preference hook starts conservatively reduced, reads the OS setting and follows live changes. Gallery/detail transitions, review disclosure and programmatic paging use reduced alternatives. The onboarding helper delegates to that same hook. Local practice video stops autoplay; its poster remains. The 900ms practice thumbnail/pin/card choreography resolves immediately when reduced. | Component tests prove that the practice scene starts no choreography under Reduce Motion. Device checks must verify OS toggles, interruptions and all native transitions. Direct manipulation gestures intentionally remain. |
| Haptics | Shared feedback is native-only, foreground-only and coalesced within 600ms. Receipt success is tied to durable acknowledgement and guarded after terminal actions/unmount. Polling and review checkbox changes do not add repeated feedback. | Five foundation behavior checks plus extension acknowledgement tests pass. Real device availability/intensity is not verified by mocks. Information is also presented visually/textually. |
| Share Extension | React receipt scrolls. Swift startup/recovery uses dynamic colors and scalable fonts; failure controls scroll and respect host height. Standard compact presentation stays bounded, with more room requested for accessibility categories. | Generated Swift matches the authoritative plugin source. This is not a Swift compiler result or a VoiceOver/host geometry test. Instagram, TikTok, Safari and other hosts need actual iOS testing. |

## Automated checks completed

- `node node_modules/ts-node/dist/bin.js -P scripts/tsconfig.json scripts/testFieldnotesFoundation.ts`: **35 checks passed**, comprising 30 contrast combinations and five feedback behavior checks.
- `node node_modules/ts-node/dist/bin.js -P scripts/tsconfig.json scripts/testFieldnotesSavedComponents.ts`: **42 assertions passed**, including the 50/51 feature cutoff, 100 compact rows, search/empty states, callback identity, scalable text branches and snapshot-only photo policy.
- `node node_modules/ts-node/dist/bin.js -P scripts/tsconfig.json scripts/testOnboardingV2MagicRender.ts`: **24 practice-scene combinations passed**, plus processing timing, native text-host invariant and persisted resume checks.
- All **29 onboarding contract suites passed**. Older assertions were updated only where `git show ca08c154:<file>` or the new presentation extraction established obsolete expectations. Runtime routing, offline fixture generation, durable queue matching and auth logic were not changed to satisfy visual tests.
- Review evidence reports **24 actual component renders**, **25 passing review scripts**, **15 actual extension-root renders** and **10 passing extension scripts**. These use native host/bridge doubles and are not device screenshot evidence.
- Integrated TypeScript passed at the phase checkpoint. Exact commands and results are in [detail-saved-onboarding-tests.json](artifacts/fieldnotes-implementation/detail-saved-onboarding-tests.json) and [review-extension-phase.json](artifacts/fieldnotes-implementation/review-extension-phase.json).

Contrast tests use the standard relative-luminance calculation on solid semantic colors. They cover Light and Dark text/secondary/accent against canvas, surface and elevated surface; primary-action text; both save-gradient endpoints; and success, warning and danger pairs. They do not establish all non-text boundary, image-overlay or native-system contrast requirements. Disabled styling is not counted as normal readable text evidence.

## Native acceptance still required

| Check | Concrete acceptance exercise |
| --- | --- |
| VoiceOver end to end | Traverse map controls, markers, Saved, detail, source, gallery, More, reminder, Activity, Quick Check, multi-select, onboarding, auth and Settings. Verify selected/checked/busy announcements, meaningful names, logical ordering and no inaccessible essential action. |
| Focus ownership | Open/close each sheet and modal, use gallery paging, show an error, return from a source app and complete auth. Confirm focus enters the new surface and returns sensibly without entering background content. |
| Dynamic Type and small screens | Use default, large and a representative accessibility-large size on a small iPhone and a large device. Check critical actions, reminder distance controls, permission copy, long place/address text, zero-photo fallbacks and all 20+ Saved states. Scroll and keyboard access must remain usable. |
| Reduced motion | Enable before cold launch, change while open, interrupt the practice transition and return from background. Verify the final place/status remains available without a flight, pulse or forced camera motion. |
| Touch and gesture alternatives | Exercise gallery arrows, separate candidate checkboxes and photos, close controls, dock and native map targets. Check adjacent target overlap and gesture conflicts at the device's actual scale. |
| Real media/readability | Verify no-photo, one-photo, multi-photo, failed/unavailable original post and long original captions in Light and Dark. Check text over photographs and native map labels, not just solid token pairs. |
| Share hosts | Test the embedded extension in Instagram, TikTok, Safari and representative system hosts, including pending/accepted/error, large text, safe areas, VoiceOver and return-to-app behavior. Android captures cannot establish this iOS result. |

Screenshots can show native layout but cannot establish VoiceOver order, focus restoration or accessible interaction. Host-mock component tests can detect contract regressions but cannot establish pixel geometry. Those distinctions remain explicit until the Development build and founder/device QA supply the missing evidence.
