# Saved-place/source data model (Production read-only audit, 2026-10-08)

Evidence: live `pg_constraint`, `pg_policies`, `pg_trigger`, `information_schema`, and function-definition queries against project `rlqvxdwtetxsqxhqztkw`; repository migrations `20260822000001`, `20260822000002`, `20260905000005`, `20260906000003`; exact public client source `ded040465...` and build-58 source `ca08c154...`. This is a map of relevant relationships, not an assertion that every table in `public` was audited.

Every `public` table listed below has RLS enabled. Only the stated owner/client policies grant authenticated access; service-role/server paths bypass ordinary client RLS. `place_video_media`, transfer grants, media tasks/runs, recognition state and public-share internals have no direct authenticated owner policy in the inspected `pg_policies` list; their server/RPC entry points must provide authorization. `places` is readable/insertable by authenticated users; profiles are self-scoped.

| Object | Key/owner and relationship | Deletion/RLS/trigger behavior | Mutation/read path |
|---|---|---|---|
| `auth.users`, `profiles` | Auth `id`; profile `id` is the same user identity. Anonymous and permanent accounts are distinct rows in the cross-account flow. | Profile owner RLS; auth identity is not a source-content owner. | Auth service and `handle_new_user`; client profile reads. |
| `places` | Global canonical place `id` (Google identity lives here); no per-user owner. | Referenced by saves and video media; delete cascades to both. | Place resolution/merge RPCs and server workers. |
| `saved_places` | PK `id`; `user_id` FK to `auth.users` (cascade); `place_id` FK to `places` (cascade); unique `(user_id,place_id)`. Owns `notes`, `ai_note`, radius/notification/reminder counters, archived/visited state, and legacy primary `source_url/source_type`. | Authenticated owner SELECT/INSERT/UPDATE/DELETE; `set_updated_at`, video-AI-note, correction/dispute and video-media place-sync triggers. Deleting a save cascades to its `saved_place_sources` and `notification_events`, but sets several job/result references null. | Client `savedPlacesService` CRUD; privileged save/correction/share RPCs and Edge/worker. The v1 transfer can change `user_id` without a child-owner trigger. |
| `saved_place_sources` | PK `id` is a **relationship row**, not a reusable source object. `saved_place_id` FK to save (cascade); `user_id` FK to auth (cascade); unique `(saved_place_id,identity_key)`; at most one primary link per save. `identity_key` canonically identifies reusable video/content, while URL/creator/note fields describe that association. | Authenticated SELECT only, RLS `user_id=auth.uid()`; no client UPDATE/DELETE grant. `saved_place_sources_enforce_owner` rejects INSERT or changes to `saved_place_id,user_id` unless `user_id=saved_places.user_id`. Also updated-at, recognition-note and global-video sync triggers. **No reciprocal trigger on a parent `saved_places.user_id` update.** | Backfill and `attach_saved_place_source`, correction/shared-place RPCs, privileged Edge/worker paths. Both iOS versions hydrate these rows by saved-place ID, but RLS still filters each child. |
| `place_video_media` | PK `id`, unique `(place_id,identity_key)`; global place/content media, no `user_id`. | Place FK cascade; service-role only (no authenticated table grant); frame in private storage, signed URL from `get-place-videos` after owner/community check. | Source-link triggers and worker; Edge gallery computes owner status via caller-owned `saved_places` IDs, not `saved_place_sources.user_id`. |
| `recognition_source_states`, `recognition_rejections` | Recognition state keyed by content identity/visibility scope (contextual `owner_user_id`); rejection has `user_id` and optional `source_saved_place_id` (FK SET NULL). | Separate recognition policy; not a source-link ownership substitute. No state row for this anomalous identity, and no rejection references this save. | Recognition functions/workers and feedback RPCs. |
| `share_jobs`, `share_job_place_results` | Job/result PKs; each has `user_id`; optional saved-place FKs SET NULL; result belongs to job. | Owner SELECT RLS; job saved-place FK SET NULL. Result preserves original saved-place reference on update. | Share Edge/worker, review/correction RPCs. No job or result references the anomalous save. |
| `share_media_tasks`, `share_media_runs`, `share_agent_runs` | User/job/task ownership fields; task `saved_place_id` FK CASCADE and job FK CASCADE. | Task owner guard validates changed owner/job/save fields; task state triggers. These are not freely transferable by changing only `saved_places.user_id`. | Worker and share-processing functions. No media task references the anomalous save. |
| `notification_events` | PK; `user_id` FK auth CASCADE; `saved_place_id` FK save CASCADE. Reminder history/counters otherwise live on `saved_places`. | Owner SELECT/INSERT RLS. The one event for this save is owned by the current saved-place owner. | Nearby notification logic and client reads. |
| `public_place_shares`, `public_place_share_saves` | Public-share creator `created_by`; optional `source_id` FK to relationship row SET NULL. Save record has `user_id` and optional `saved_place_id` FK SET NULL. | Source-link deletion can break public-share provenance; no public-share row points to the anomalous source link. | Public-share RPCs and Edge/client. |
| `onboarding_v2_sessions`, `onboarding_account_transfer_grants` | Session has current `user_id`, historical `anonymous_user_id`, `permanent_user_id`, tutorial save FK SET NULL. Grant binds source/destination/session and stores completed result. | Session owner SELECT; grants not directly readable by authenticated clients. | Old v1 `begin/complete/finalize/resume` RPCs; build 58 expects distinct V2 begin/complete RPCs, not yet in Production. |

There is **no separate user-owned canonical source row** in the current model. Content identity and global place-video media may be reused across users. Each `saved_place_sources` row is the user's association to one save; `user_id` redundantly records that save's owner for RLS and must match it. `original_url`, creator fields, `first_attached_at`, and the transfer grant are provenance; retaining a former owner in the association's `user_id` is not an intended provenance mechanism.

`get-place-videos` is a special server read: after authenticating the caller, it uses service role to find the caller's save IDs and then sources by **save ID**, not child `user_id`. This does not redefine child ownership. Both public 1.4.55 and 1.5.58 `savedPlacesService` first read owner-scoped saves, then source rows by those IDs through RLS; both `placeSourceCards` versions can fall back to the legacy parent `source_url` when the child is hidden.
