# Ownership invariant experiments

1. **Rejected: child-only owner trigger plus V2 parent `FOR UPDATE` locks.** The isolated two-session test committed a transferred B parent/original child and a late A child, leaving one mismatch. The child BEFORE trigger could check A before the parent changed; the original FK referenced only the stable saved-place ID. No such candidate is deployable; the exact rejected SQL remains at repository root for forensics.
2. **Selected: composite referenced owner key with `ON UPDATE CASCADE`.** Applied to an isolated clone of the repaired Production restore (627 saves, 545 source links, zero initial mismatches). Both constraints validated and the source/save mismatch count stayed zero. A rerun of the formerly failing four-case concurrency harness passed; its late A insertion was rejected by `saved_place_sources_owner_fk` rather than committing a split graph. The core V2 and security fixtures passed. The historical-mismatch failure fixture now temporarily removes the FK only in a rollback-only local savepoint to prove V2 still rejects a pre-existing bad graph.
3. **FK independent of the old guard.** A rollback-only fixture disabled the user-defined child-owner trigger while leaving internal FK triggers active. A wrong-owner insert still raised a foreign-key violation. Parent owner update cascaded the child without changing its row ID or identity; reattachment with both keys changed succeeded; parent deletion removed the child without an orphan.
4. **Second discovered race: duplicate-source loss despite zero mismatches.** The initial composite-FK V2 kept A's duplicate graph, so a late A source after B's copy remained a valid A-owned link but never reached B (`late_a=1, late_b=0, mismatch=0`). This fails source-preserving transfer semantics. The parent-lock/converted-source guard in migration `20261009000004` closes it for both V1 and V2: deterministic two-session transfer-first attempts reject, child-first attempts commit and are copied (`late_a=1, late_b=1, mismatch=0`).
5. **Third discovered race: a whole new anonymous save after conversion.** A source guard does not cover a late parent INSERT. Migration `20261009000005` serializes anonymous save creation against the onboarding session: deterministic transfer-first creation rejects; save-first creation plus source commits, then V2 transfers both. Neither change weakens the composite FK.
6. **Rejected harness interleavings, not product faults.** A 0.7-second child-first signal sometimes expired before PowerShell observed the advisory lock, so the forced-order harness now holds that fixture transaction for two seconds. The first duplicate stress fixture accidentally interpolated `$i:a1`/`$i:a2`/`$i:base` as PowerShell scoped variables, collapsing distinct identity keys; braces around `${i}` fixed the fixture. All failed clones were local and dropped.
7. **Not selected: RPC-only locks, serializable V2 alone, or a deferred trigger.** They can improve one path but leave other privileged writers and legacy parent updates to coordinate correctly. The declarative key covers ownership equality at the table boundary. The additional narrowly scoped guards address *post-conversion source/save loss*, a distinct requirement.

The full repeated/interleaving totals, deadlock observation, and client/security/failure gates are recorded in `V2_TRANSFER_CONCURRENCY_REPORT.md` and `V2_TRANSFER_FINAL_QUALIFICATION.md` after the stress run. No Production schema or data was touched during these experiments.
