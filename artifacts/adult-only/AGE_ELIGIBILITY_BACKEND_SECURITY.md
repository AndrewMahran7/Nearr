# Backend authorization and current proof

The Development-only migration creates the owner-readable RLS table and service-role-only `is_adult_eligible_for_ai(uuid)` RPC. `declare_age_eligibility_18_plus(boolean)` derives its principal from `auth.uid()`, serializes same-user calls with an advisory transaction lock, and refuses conflicting repeat answers. The queue triggers reject ineligible inserts/requeues into `share_jobs` and `share_media_tasks`; they do not rewrite or erase historical rows.

The local Edge changes check age after authentication in `create-share-job` and the old synchronous `process-share-link` route, before metadata/provider work. `process-share-jobs` checks claimed jobs and delayed worker callbacks. The media worker checks at task start and again before transcription, OCR, and model calls. Known ineligibility records `needs_help`/`age_eligibility_required`; check outages fail closed and retry rather than authorizing a provider call. A forged request boolean cannot substitute for the server record; task/callback checks use stored owners, not a caller-provided ID.

Nearr-Dev schema migration applied 2026-10-18 to project `qnfxnmvxpjzfydgudtvs`; post-migration SQL transaction tests passed for unknown denial, adult declaration/idempotency, locked conflicting answer, underage lock, owner RLS, client write denial, service-RPC denial, anonymous transfer propagation/idempotency/destination restriction, and ineligible share-job/media-task requeue denial. Test writes were rolled back and post-test persisted row count was zero. Edge and Railway code are **local only**, not deployed; therefore a live end-to-end authorization guarantee has **not** been demonstrated. Production remains on its previous code and is not protected by these changes.

Remaining security proof: direct queue insertion, transfer concurrency, JWT expiry, authenticated legacy 1.4 calls, queued/in-flight provider-call counts, and a deployed worker/Edge negative test. No Production conclusion can be drawn from the local tests.
