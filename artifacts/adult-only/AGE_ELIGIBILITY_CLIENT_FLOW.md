# Nearr 1.5 client eligibility flow

Offline Phase 1 keeps its deterministic bundled tutorial and does not ask Supabase for age. Once anonymous Phase 2 is reached, or a permanent session is restored/created, `AuthGate` requests the server decision. The root Stack remains mounted for Expo Router, but the full-screen safe-area gate covers and disables interaction with it until the decision is adult. A pending account can declare 18+ or under 18. Loading, offline/error, underage, and revoked states fail closed; restricted users see a support/data-request link and a sign-out path. The decision is refreshed on foreground and onboarding-stage change.

Existing adults do not repeat the step once their server row is present. Existing unknown-age users do not repeat onboarding. Anonymous declarations are intended to propagate through the one-time V2 transfer to a new permanent account; a previously restricted destination is not overwritten. This transfer interaction is implemented but not yet exercised end-to-end on a device.

The new extension/host-handoff screens distinguish `age_eligibility_required` from success and state that no job was queued. This requires a replacement native iOS build for the Share Extension. In the legacy in-app share path, the optional direct Gemini fallback is disabled on mobile; its local heuristic remains, and server submission must authorize AI. A mounted-but-hidden route could otherwise run effects; an age-access context now prevents the share screen from mounting its processing effects before approval, and notification/geofence setup is deferred. The backend—not visual obscuring or context—is still the security boundary. Physical navigation, offline/retry, account-switch, and reinstall QA are outstanding.
