# Recommended recognition route

Preferred: retain the existing dedicated OpenAI Responses adapter, OpenAI transcription and current deterministic resolver/Quick Check/save pipeline. Do not repurpose the Gemini key, bypass guardian authorization, revive automatic-deep/Jev experiments, or change the audience to adult-only. Account/consent/processor qualification is the missing condition; another rewrite does not resolve it.

The adapter already enforces a fixed OpenAI endpoint, redirect rejection, explicit route and enable flag, timeout at most 90 seconds, 12 frames, 1 MiB/frame, 6 MiB total frame bytes, 24k context characters, 8k output tokens and 256 KiB response. It parses grounded evidence and supports targeted saved-place notes. Its tests pass, but mocked success is not recognition quality. Model choice remains unqualified: use a currently supported multimodal model accessible under the approved account and evaluate it before choosing on cost. No model-access claim is made.

Before enabling: implement the reviewed guardian mechanism from PROVIDER_CONTRACT_ELIGIBILITY, teen-appropriate output safety/incident escalation, provider-specific disclosures, processor approval and privacy controls. Issue a dedicated least-privilege recognition credential through a secret manager, not chat. Pin the selected model and record pricing/retention evidence. Keep DB and worker switches closed until the bounded benchmark and adult/minor flows pass. Recheck authorization immediately before acquisition, audio/OCR, recognition, AI note, retries and saves; no cross-provider fallback.

## Hosted alternative considered

Anthropic permits customer applications under commercial terms and has explicit minor-facing guidance. It is a credible hosted alternative, but no existing applicable account/credentials or completed safeguards are evidenced. Adopting it requires an image/text Messages adapter, output normalization into the same evidence schema, a transcription decision, a provider-specific notice and reviewed database route; the existing `openai_only` gate must not be mislabeled to dispatch Anthropic. It is not a shortcut around source-media privacy or regional consent.

## Concrete private-model fallback plan

Use `Qwen/Qwen2.5-VL-7B-Instruct`, whose [publisher card](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct) declares Apache-2.0 and documents image/text/video and structured output. [vLLM](https://docs.vllm.ai/en/latest/models/supported_models/) supports the model family. Pin a reviewed weight revision and container digest, preserve license notices, and scan dependencies before provisioning. No model artifact has been license-archived or deployed in this task.

Keep Railway for queue, acquisition and deterministic resolution. Add one private, authenticated inference endpoint on a separately approved GPU host; implement `PrivateVisionProvider` against `ModelProvider.analyze` and `generateTargetedNote` using bounded Chat Completions messages and the existing JSON evidence validator. Send selected resized frames and bounded text, not raw complete social videos. Preserve response-size/timeout/concurrency limits, reject redirects and arbitrary URLs, redact content logs, set no-training/no-logging controls, and fail closed with no hosted fallback. Add an explicit `private_qwen` qualification route through an additive reviewed migration; do not reuse `openai_only`.

Initial sizing **estimate, not measured**: a 24–48 GiB GPU, concurrency 1, 4–6 resized frames, 8k context, 2k output tokens; use 48 GiB if unquantized weights plus cache/vision working memory do not fit. Validate actual peak memory before increasing concurrency. Start with US private infrastructure for a US-only qualified canary; additional regions require appropriate hosting/data-transfer arrangements. This does not promise worldwide coverage. Keep audio on the existing self-hosted transcription service only after its model/license and operations review; local OCR can avoid another API processor.

Hosting cost must be quoted for a single instance, not confused with per-GPU multi-GPU cluster pricing. [Lambda pricing](https://lambda.ai/pricing) is a current primary reference, but displayed multi-GPU configurations are not a usable Nearr purchase quote. Planning envelope: if an approved single GPU costs $1–$3/hour, continuously running compute is $720–$2,160 per 30-day month before storage/network/tax; this is arithmetic, not an offer or availability claim. At measured service time T seconds and concurrency 1, theoretical upper throughput is 3600/T requests/hour, lower under real queueing. Latency, accuracy and effective per-submit cost are unknown until measured. Do not claim a small open model equals the current recognition baseline.

Operational additions: GPU provisioning/patching, model cold-start, private ingress, monitoring with redaction, rate limits, health checks, bounded queue and incident response. A GPU subscription/new paid commitment needs authorization. No infrastructure was purchased. This fallback is technically concrete but slower and operationally heavier than qualifying the existing OpenAI path.
