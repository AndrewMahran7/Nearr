The additive migration `20261028000001_nearr_free_only_release.sql` adds explicit `release_mode` with default `paid`; existing disabled or temporarily unavailable behavior remains unchanged. Selecting `free_only` requires `release_qualified=true`, `enforce_allowance=true`, `sales_enabled=false`, and exactly three free finds. It does not require a fabricated verified paid catalog or RevenueCat app ID. Paid-mode sales/allowance retain catalog/release requirements.

This is an **initial-launch-only** path, not a safe general paid-to-free cutover. The reviewed follow-up refuses activation when **any** Nearr Plus customer identity or entitlement history exists, including inactive/expired snapshots and customers whose receipt has not arrived yet. Config transitions, paid identity writes and all entitlement writes share a transaction-scoped database lock. If free-only activation wins, late paid identity/active receipt writes reject atomically; the Edge handlers return `409 release_mode_changed`. If a paid identity/grant wins, activation rejects and paid mode remains. Snapshot RPCs acquire the shared release lock before user/period locks, preserving multi-identity webhook compatibility. Protected config/customer/entitlement writes require normal `READ COMMITTED`; fixed-snapshot isolation levels are explicitly refused with `plus_release_requires_read_committed` because an advisory lock cannot refresh a Repeatable Read snapshot. Existing legacy Pro customers, Apple receipts and RevenueCat identities outside these new tables must still be reconciled before activation: empty new tables alone are not proof that no paid obligations exist. No production history may be deleted to satisfy this gate.
