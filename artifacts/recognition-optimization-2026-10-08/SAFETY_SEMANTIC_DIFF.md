## Explicit remaining limits / deployment constraints

- Candidate transactions and final parent transition are separate. If an authorized save wins first and a correction wins before the final transition, the later transition is rejected; the earlier committed save is not retroactively undone. Existing correction/undo owns that behavior. This is not an all-stops atomic batch commit.
- Completed-parent supplemental enrichment keeps its existing target/provider/source-specific contract. Its result/source writes do not use the new ordinary-recognition parent-processing lock; this patch does not claim a new atomic guarantee for that path. AI-note task status carries generation fields, and existing note target guards remain.
- Diagnostic rows and network/provider work already underway may finish after cancellation. Cooperative abort and stage checks prevent further work where observed; HTTP cancellation cannot prove unbilled work. No avoided-spend claim is made.
- The deterministic shadow router cannot authorize saves or skip live deep verification. Labeled raw source evidence is insufficient to promote a faster route.
- Rollout requires SQL migrations before the new Edge callback. Deploy a claim-bearing worker before enforcing claim tokens in Edge; old Edge ignores the extra token. No deployment performed here.
- Root metadata/cache completion paths still use their existing status guard; this media-specific repair does not assert a transaction-level generation guarantee for unrelated tasks.
- Billing: if the guarded final transition loses a race, the existing reconciliation still reads authoritative terminal facts. A pre-existing full-callback retry gap remains when an earlier terminal commit succeeded but settlement failed: terminal-parent/task routing can return before that reconciliation. This patch does not claim to repair or conceal the gap; the existing reconciliation inside `finalize` is preserved.
