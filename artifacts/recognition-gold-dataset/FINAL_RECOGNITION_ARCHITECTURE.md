# Frozen final candidate architecture

Status: sealed confirmation running. This is a frozen candidate, not yet a proven winner or a deployed change. See `FINAL_CANDIDATE_PREREGISTRATION.json` for immutable policy and code hashes.

1. Prepare the original timed visual evidence and available source text. Preserve source geography, entity roles and physical branch specificity. Keep the repaired baseline frame budget and model prompt.
2. Run the normal cheap multimodal pass. If the result is fully valid and empty, with no partial place or multi-place intent, return review. This does not declare the video a negative. Parse/transport errors never qualify.
3. Otherwise retain the repaired baseline specificity gate, Places resolution and server-owned autosave decisions. In the legacy food-venue lane, a candidate categorized only as a nonfood parent cannot be saved as the tenant.
4. Weak named identities, partial evidence and multi-place intent retain the shared Deep path and existing review policy. No new review suggestion is promoted to an autonomous save.

This is an adaptive stopping policy with the original recognition models, not a new model. Development/calibration preserve all 19 correct autonomous resolutions. The category veto removes one parent substitution; other wrong/unverified saves remain. Cost-per-correct reductions are about 19% in common-prefix replay. One correct development review candidate is lost when the earlier empty pass stops; the tradeoff is explicit.

The final comparison runs the baseline on the sealed sources and derives the candidate from the exact same immutable normal outputs, without labels. This controls stochastic model variation. Candidate cost includes the recorded prefix calls it would execute; all actual paid baseline calls still count toward experiment spending. Full baseline latency is retained as a conservative bound, with no credit for skipped work. The live five-case pilot separately verifies that the early stop executes without a Deep request.

Text-only routing and all four fitted text routers are rejected. The combined schema/structural variant is rejected for new wrong/incomplete multi-place saves. Adaptive frame reduction, broad literal-street enrichment, automatic OCR/ASR and the prior geometric verifier have not earned inclusion. Retrieval and Jev remain off. Experimental code remains isolated from default runtime settings.

The runtime already bounds selected frames, Deep attempts and job wall time; experimental metering additionally reserves every physical provider request and enforces the cumulative $50 cap. The current research guard is a batch guard, not evidence that a new production per-job dollar cap has been deployed. Per-job budget instrumentation and the omitted acquisition/DB/device timing stages must be addressed explicitly in any integration report.

No new answer cache, model-prior authority, client confidence permission, database migration or Production deployment is part of this candidate. The dataset and media stay private. An approved durable recovery location remains an administrative follow-up; verified backups are currently local on the same volume.
