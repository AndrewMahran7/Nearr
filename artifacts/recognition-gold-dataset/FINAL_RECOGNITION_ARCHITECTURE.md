# Recommended Development architecture

The frozen valid-empty-review plus food-parent-veto policy is a statistically supported cost improvement over the repaired baseline. All 9/56 held-out correct autonomous resolutions, 17 autonomous outputs and their identities are unchanged; no new wrong confident result or complete multi-set regression occurred. The conservative cost-per-correct ratio is 0.909136, with a 95% connected-group bootstrap interval [0.825217, 0.978259] (10,000 draws; 60 groups). This is at least 9.09% cheaper at the adversarial point estimate; the interval corresponds to a 2.17%–17.48% reduction. It narrowly misses the suggested 10% material point target, which was not the preregistered statistical acceptance gate.

1. Prepare the original timed visual evidence and available source text. Preserve source geography, entity roles and exact physical branch specificity. Retain the repaired prompt, Gemini 3.5 Flash Lite, up to 24 scheduled frames and six-frame diverse Deep selection.
2. Run the cheap normal model. Fully valid empty output, without canonical/partial identities or multi intent, returns review before Deep. Invalid schema, provider failure and missing source evidence do not qualify. It does not declare a negative.
3. Named actionable evidence retains original Places resolution and authoritative server decisions. The legacy food-venue path adds only a veto when explicit food evidence resolves to an exclusively nonfood parent category. It never grants autosave.
4. Weak identities, partial evidence and multi intent keep the original shared GPT-5.6 Sol Deep path, up to two attempts, and review policy. No automatic promotion of review candidates is added.

The isolated integration contains only those policies and their default-off flags. Rejected experimental routers, OCR/ASR changes, frame selection, schema changes, retrieval, Jev, atomic-multi changes and strict tenant/name matching are not shipped in that branch. Existing evidence reuse and correction-aware cache safeguards are preserved; no new final-answer cache is introduced.

Held-out routing: 41/62 (66.13%) normal visual/Places, 15/62 (24.19%) Deep review and 6/62 (9.68%) empty review. Gemini is called on 100%, Sol on 24.19%, Places search on 90.32%; no new ASR, OCR or retrieval call is part of this retained-evidence comparison. Full provider/tier totals are in `FINAL_AGGREGATE_METRICS.json` and `LATENCY_BY_TIER.md`.

Existing native bounds include 180-second source duration, 24 selected frames, two Deep attempts and 480-second job wall time. The experimental guard enforces per-request reservations, model/rate-specific call ceilings, request timeouts and the $50 cumulative cap. This is not a deployed cross-worker/Edge per-job dollar ceiling. Such a shared per-job spend guard, durable accounting across retries, and complete acquisition-to-DB/device timing remain production-readiness gaps; the cost winner must not be described as completing them.

This result does not establish production safety or improved identity accuracy. Held-out precision is only 9/17 = 52.94% (group-bootstrap 95% interval 27.78%–80.00%); 8/62 outputs are wrong or unverified against the frozen exact standard. Coverage is 17/56 = 30.36% of exact-positive submissions (17/62 overall). No 99% precision or population equivalence claim is made. Multi-place exact autonomous sets remain 0/8; detection is 3/8. Missing parsed provider country/region fields mean geography check coverage is 0/17, so reported zero geographic mismatches is not evidence of zero errors. Wrong/unverified branches are 3/12; negative autonomous false positives are 0/6.

Timing starts with retained evidence and ends at authoritative server finalization planning. It excludes live media acquisition, fresh ASR, queueing, database writes and device delivery. Candidate replay retains the entire baseline latency plus measured local policy overhead; no skipped-work speedup is claimed. Costs are provider usage times frozen tariffs, not invoice totals. The one unknown fixed-price request remains unknown in primary metrics; ranges use its reserved $0.032 maximum.

Deployment is held because the shared Development worker's actual deployed commit is unverified and concurrent source has diverged. The isolated integration is reviewable and portable. No Production or Nearr 1.5 deployment/change occurred.
