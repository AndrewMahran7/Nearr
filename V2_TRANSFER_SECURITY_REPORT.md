# V2 transfer security qualification (local restore)

`scripts/testSafeOnboardingV2Security.sql`, `testSafeOnboardingV2Core.sql`, `testSavedPlaceSourceOwnerInvariant.sql`, and `testLegacyV1TransferSafety.sql` passed against the final ordered migration replay of the repaired Production restore. The fixtures are synthetic and rolled back.

Checks include no anonymous/public EXECUTE of the V2 RPCs, an authenticated anonymous user unable to begin another user's session, malformed/weak/tampered/expired grants rejected, anonymous completion rejected, malformed non-anonymous source rejected, foreign-destination replay rejected, source-save UUIDs validated, and a zero-real-save/synthetic tutorial case that cannot manufacture a save. Both accounts' saved-place/source RLS visibility was checked after V1 and V2 conversion. The composite FK still rejected a wrong-owner child with the user-defined owner guard disabled inside a rollback-only fixture, so service-role/RLS bypass cannot waive ownership equality.

The transfer secret is intentionally a bearer capability; possession of an unexpired valid secret by a different authenticated permanent account is not proven safe by these tests and remains an account-linking security assumption. Release qualification must not describe this as origin-bound authorization. Administrators who explicitly disable/drop integrity constraints or triggers are outside the supported-writer model. No Production V2 RPC or transfer was deployed in this task.
