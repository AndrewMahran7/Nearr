# Saved-place/source writer inventory (2026-10-09)

Scope: repository-wide search of SQL migrations, RPC bodies, Edge Functions, workers, client services, and scripts, cross-checked against the live-function catalog in an isolated restore of the Production schema. The database boundary, not this inventory alone, must enforce the invariant for privileged or future writers.

| Writer / path | Runtime mutation | Ownership protection |
|---|---|---|
| `attach_saved_place_source` RPC | INSERT source; on dedupe UPDATE source metadata; may UPDATE parent legacy source fields | Checks caller/user, locks parent, child owner guard; new composite FK protects even a stale direct insert. Converted-anonymous source associations are rejected. Called by `services/savedPlaceSourcesService.ts` (manual/client save) and `supabase/functions/process-share-jobs/recognitionCache.ts` (recognition/worker). |
| `correct_saved_place_provider` RPC | INSERT/UPDATE source associations while correcting/merging saved places | Existing owner guard and new FK validate every resulting association, including a changed `saved_place_id`. No parent owner change. |
| `save_shared_place` RPC | INSERT/UPDATE save and source association | Existing owner guard and new FK; destination-owned association only. |
| `complete_onboarding_account_transfer` (public 1.4.55/V1) | UPDATE unique parent owner; duplicate branch historically DELETEd the anonymous save | Composite FK `ON UPDATE CASCADE` repairs unique branch automatically. The V1 compatibility amendment now copies missing source identities and retains the anonymous duplicate graph. |
| `complete_onboarding_account_transfer_v2` (new) | UPDATE unique parent owner; INSERT missing destination source identities for duplicate save | Composite FK cascades unique children, rejects stale-owner inserts; V2 retains anonymous duplicate graph and grant/result replay. |
| `services/savedPlacesService.ts` and client save/update/delete flows | Direct saved-place INSERT/UPDATE/DELETE; no direct child write | Parent INSERT uses caller owner; metadata/visited/reminder edits do not change owner; DELETE cascades. FK protects any owner change attempted by a privileged path. Converted-anonymous INSERT is serialized/rejected by migration `20261009000005`. |
| Other save creators: `admit_recognition_answers_v2`, named-lead completion, soft-alternative promotion, share-job result, `process-share-link`, public-share save | INSERT or metadata/place correction for `saved_places`; source attachment follows RPC/trigger | New key applies when source rows exist. A new save starts childless; existing child owner guard and FK govern attachment. |
| Other source touches: recognition-note and video-media sync triggers; `get-place-videos` | Metadata/media UPDATE or read only | They do not set child `user_id`; composite FK remains enforced. |
| Historical migrations/backfills and test/fixture scripts | One-time or isolated direct INSERT/UPDATE/DELETE of sources/saves | Not live Production writers. Any future migration still cannot violate the composite FK unless it explicitly disables/drops integrity enforcement. |
| Privileged service-role or SQL direct table write | Potential INSERT/UPDATE/DELETE on either table | RLS is not sufficient for service role. The new composite FK protects successful commits even when RLS is bypassed; converted-account triggers prevent stale post-transfer associations/new saves. Only an administrator deliberately disabling constraints/triggers can bypass these boundaries. |
